# Feedback

Comments, criticism, and improvement ideas people leave on Twitter,
LinkedIn, or anywhere else during the public launch. Gitignored — this
is a private working record for the founder and whichever agent is
active, not part of the shipped project (people didn't sign up to have
their comments published in the repo).

## File naming

```
feedback/<platform>_<YYYY-MM-DD>.md
```

Examples:

```
feedback/twitter_2026-09-19.md
feedback/linkedin_2026-09-19.md
```

One file per platform per day is fine to start; if volume picks up,
split further (e.g. by post/thread) rather than letting one file grow
unbounded.

## What goes in it

For each comment worth keeping:

- The comment itself, quoted plainly (no editorializing in the quote)
- Who said it, if it matters for context (role/background, not
  necessarily their handle if that feels off to keep around)
- Platform + rough date
- A one-line read on what it's actually asking for, if it's not
  obvious — comments are often compressed; the real ask underneath is
  sometimes a different (and often bigger) feature than the literal
  words

Not every comment needs a response or a decision recorded here — this
is a capture point, not a triage system. When something here turns
into an actual decision (a new feature, a repositioning, a task),
that decision belongs in `tasks/plan.md` or `docs/ideas/getsloth.md`,
not just left sitting in this file.
